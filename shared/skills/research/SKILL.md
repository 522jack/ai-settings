# Исследование

Для разового запуска достаточно результата в чате или запрошенного документа. Если результат нужен другому этапу или для возобновления, обновите раздел по `$HOME/dotfiles/ai/shared/rules/task-report.md`.

Вход: topic, context и constraints. Не меняйте продуктовый код и не превращайте исследование в разрешение реализации. Выберите только направления, дающие отдельный сигнал:

| Track | Когда | Исполнитель |
|---|---|---|
| Codebase | Existing code/patterns/modules | Explore |
| Architecture | Module/layer/API boundaries | architecture-expert |
| Web | Industry practice/benchmarks/external approaches | source-researcher, focus web |
| Docs | Конкретный внешний API/framework | source-researcher, focus library-docs |
| Dependencies | Добавление/замена JVM/KMP dependency | source-researcher, focus dependency-intelligence |

В одиночном режиме соберите источники самостоятельно. В режиме с субагентами разделяйте работу, когда нужен независимый результат или полезна параллельная работа. Сходные направления можно объединить. Для передачи используйте нужные части [expert-prompts.md](references/expert-prompts.md).

Проверяйте меняющиеся факты первичными источниками, реализуемость — минимальным экспериментом в пределах задачи. Сопоставьте выводы, расхождения и пробелы.

Проверьте вывод по исходному вопросу и доказательствам. Если нужен отдельный проверяющий и выбран режим с субагентами, используйте [auto-review.md](references/auto-review.md).

Уточняйте через доступный chat question tool (или чат при отсутствии инструмента), по одному существенному вопросу за раунд. Уже имеющуюся авторизацию сохраняйте; исследуемые пробелы решайте без пользователя. Блокирующее user решение разрешите до готового отчёта, external unknown храните с evidence/owner. Не задавайте вопросы через файлы.

Сообщите рекомендацию, определяющие факты, пробелы и необходимое решение. Если нужен отчёт, используйте раздел `Research` по [artifacts.md](references/artifacts.md).
