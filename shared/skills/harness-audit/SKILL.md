# Аудит харнесса

Сначала соберите факты штатным read-only скриптом; он выводит JSON в stdout и не меняет файлы:

```bash
python3 scripts/audit.py --root "$HOME/dotfiles/ai" --home "$HOME"
```

Путь к скрипту разрешайте относительно этого SKILL.md. Для другой установки передайте её `--root` и `--home`. `--discovery-dir` задаёт точные каталоги навыков; `--include-plugin-cache` проверяет кандидатов из кэша, а не доказывает их присутствие в живой сессии. Для штатной валидации передайте `--validator /path/to/quick_validate.py`. Не читайте конфиги или журналы целиком в ответ инструмента.

По запросу измерения расхода запускайте `--usage --session-dir /path/to/codex/sessions`. Скрипт берёт последний cumulative `total_token_usage` каждого журнала, сохраняет cached input отдельно и не складывает повторяющиеся token_count events. Он не оценивает стоимость в деньгах и не извлекает текст пользователя. Отсутствие cumulative usage означает отсутствие измерения.

Различайте каталог имён/описаний, тело активного SKILL.md, прочитанные references и реально раскрытые runtime инструкции. Размер всех файлов на диске не равен входному контексту каждого запроса. Tokens точные только при доступном `tiktoken` для выбранного encoding; иначе сообщайте символы и байты.

Проверьте по текущей сессии, какие кандидаты реально видны. Рекомендуйте сначала устранение доказанных дублей/дрейфа и конфликтов, затем короткие различимые descriptions и перенос условных режимов/шаблонов в references. Сохраняйте авторизацию, критерии остановки и нестандартные инварианты; не добавляйте универсальные экспертные панели.

Для изменений обычного риска: подготовьте изменение, выполните релевантные существующие проверки и независимое семантическое ревью. Для auth, данных, схем, concurrency, public API и архитектуры применяйте полный `finalize` + `acceptance`. Сам аудит не запускает эти pipelines и не разрешает commit/push или внешние действия.

Итог: конкретные пути, приоритеты, измеренные размеры, ожидаемый механизм экономии и пределы проверки. Не заявляйте процент экономии до сравнения сопоставимых реальных запусков. После изменения discovery/config нужна новая сессия для проверки эффекта.
