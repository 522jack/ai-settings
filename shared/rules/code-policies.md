# Правила работы с кодом

- Следовать соглашениям проекта и обновлять непосредственно связанные документы. Короткий комментарий нужен, когда совместимость, внешний контракт или крайний случай объясняют неожиданное поведение.
- Сохранять область задачи и существующие паттерны. Существенные архитектурные компромиссы кратко объяснять. Отдельный структурный рефакторинг согласовывать с пользователем.
- Добавлять feature flags только в авторизованной задаче. Конфигурацию вести в принятом слое проекта.
- Сохранять контракты, кроме явно запрошенных изменений. О влиянии на публичный API, схему БД или CLI сообщать до правки.
- Изменения логирования регулирует [logging.md](logging.md).
