# Оркестрация

Main session отвечает за синтез, планирование и координацию. Граница действий и override пользователя определены в `shared/AGENTS.md`: продуктовый код/config/tests, тяжёлый поиск и длительные build/test/CI — специалистам; рабочие файлы процесса и `~/dotfiles/ai/**` main может редактировать напрямую. Лёгкая ориентация допустима.

## Делегирование

Перед первым делегированием прочитать [runtime-adapter.md](runtime-adapter.md) и только актуальную часть его reference. Если есть подходящий skill — сначала он; иначе профиль из `shared/agents/`, соответствующий stack/задаче. Для нетривиальной реализации/review/debug/QA применять `specialist-routing`, когда доступен.

Пакет: задача и scope; выбранный профиль; ownership путей; ограничения; source of truth; уровень риска и нужные фазы; пути применимых rules; ожидаемый artifact/verdict. Не дублировать уже прочитанные правила целиком. Не предполагать их автоматическое наследование даже в Claude: search/planning agents могут не получать общие/scoped rules. Перед навигацией специалист читает `ast-index.md`; indexed-search-first сохраняется.

Реализацию направлять stack specialist, широкий поиск — search specialist, длительные проверки — фоновому specialist, review — соответствующему expert. Main сохраняет синтез; независимые исследовательские/архитектурные заключения можно делегировать, когда это нужно workflow. Не сокращать triggered panel явно выбранного skill; набор определяется его условиями, а не постоянной максимальной панелью.

При недоступном делегировании зафиксировать `ADAPTER_LIMITATION`; это не override запрета на изменение продуктового кода main session. Не заявлять применение профиля, который не был прочитан/передан исполнителю.

## Модель и effort

Приоритет: инструкции пользователя/рантайма → настройки skill → достаточный уровень сложности. Сохранять default/inherit рантайма, если переопределение не требуется и не разрешено. Для доступных разрешённых overrides: механика/поиск — дешёвый достаточный уровень, ограниченная implementation/review — средний, сложная архитектура/security/debug — высокий. Не менять модель после ошибки без анализа её причины; effort повышать при недостаточной глубине результата. Названия моделей и mappings находятся в [current-adapter.md](references/current-adapter.md), не в общей policy.

## Квитанция

Специалист возвращает профиль, изменённые пути, проверки (command, scope, code identity, environment), verdict `PASS`/`PASS_WITH_NOTES`/`BLOCKED`, открытые риски. Main хранит подробную receipt в workflow artifact, если она нужна; пользовательский ответ содержит результат, важные проверки и ограничения без повторения полной панели. GitHub операции — через идемпотентные scripts в `$HOME/dotfiles/ai/shared/scripts/gh/`; не блокировать main на watch-командах.
