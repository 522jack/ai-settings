# Оркестрация

Режим на всю задачу определяет пользователь по разделу «Режим выполнения задачи» в `shared/AGENTS.md`. В одиночном режиме main выполняет этапы самостоятельно. Раздел «Делегирование» применяется только в режиме с субагентами.

## Делегирование

Перед первым делегированием прочитать [runtime-adapter.md](runtime-adapter.md) и применимую часть его справки. Использовать профиль из `shared/agents/`, когда его критерии нужны задаче.

Передать задачу, границы и пути, источник требований, применимые правила, ожидаемые проверки и формат результата. Путь отчёта нужен только при передаче или сохранении результата по [task-report.md](task-report.md). Специалист возвращает ответ. Перед навигацией читает `ast-index.md`.

Реализацию направлять stack specialist, широкий поиск — search specialist, длительные проверки — фоновому specialist, review — соответствующему expert. Main сохраняет синтез; независимые исследовательские/архитектурные заключения можно делегировать, когда это нужно workflow. Не сокращать triggered panel явно выбранного skill; набор определяется его условиями, а не постоянной максимальной панелью.

Если выбран режим с субагентами и делегирование недоступно, зафиксировать `ADAPTER_LIMITATION` и дождаться решения пользователя о смене режима или объёма задачи. Указывать только профили, которые были прочитаны и переданы исполнителю.

## Модель и effort

Приоритет: инструкции пользователя/рантайма → настройки skill → достаточный уровень сложности. Сохранять default/inherit рантайма, если переопределение не требуется и не разрешено. Для доступных разрешённых overrides: механика/поиск — дешёвый достаточный уровень, ограниченная implementation/review — средний, сложная архитектура/security/debug — высокий. Не менять модель после ошибки без анализа её причины; effort повышать при недостаточной глубине результата. Названия моделей и mappings находятся в [current-adapter.md](references/current-adapter.md), не в общей policy.

## Квитанция

Специалист возвращает результат, изменённые пути, проверки и открытые риски. Для повторного использования проверок передаёт точное состояние, scope и среду. Main сводит итог в чате или применимом разделе отчёта. GitHub операции — через идемпотентные scripts в `$HOME/dotfiles/ai/shared/scripts/gh/`. Для ожидания использовать неблокирующие средства.
