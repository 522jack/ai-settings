# Зависимости

Новую библиотеку или plugin добавлять только с явным одобрением пользователя. Сначала проверить, подходит ли уже установленная зависимость. Согласие на обновление существующей зависимости охватывает указанный scope и версию.

## Новая зависимость

Указать точную координату, назначение и совместимую стабильную версию из реестра. Проверить поддержку, лицензию, advisories целевой версии и используемый API. Для выбора или нетривиального adoption использовать `evaluate-dependency`. Изложить вывод кратко в плане, если он нужен задаче, или в чате.

## Обновление существующей зависимости

Проверить текущую и целевую версии, ограничения проекта/BOM, совместимость и advisories целевой версии. Выбирать версию по задаче и поддерживаемой ветке. Для major bump или изменения используемого API прочитать release notes точных версий, определить необходимые миграции и проверить затронутые вызовы. Повторная оценка выбора библиотеки нужна только при изменении её роли, поставщика, лицензии или существенного риска.

## Источники и решение

Использовать доступный реестр, официальные release notes и scanner экосистемы. JVM API сверять по исходникам точной версии через `ksrc` при наличии или по официальной документации. Подробности в [external-sources.md](external-sources.md). Если проверка недоступна, указать пробел. При обнаружении существенного advisory или новой несовместимости до изменения сообщить о влиянии, исправленной версии и доступных вариантах. Авторизованную версию не менять молча. Перед правкой убедиться, что версия разрешается в проекте, после правки выполнить затронутые проверки.
